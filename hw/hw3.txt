1. 可能发生死锁的最小 K 为 4。

当 K ≤ 3 时，如果有进程已经持有 3 台打印机，它可以完成并释放资源。
否则，每个进程最多持有 2 台。任选一个持有 h 台打印机的进程，
其余进程合计最多持有 2(K − 1) ≤ 4 台，因此至少还有 4 − h 台空闲，
足以满足该进程最多 3 − h 台的剩余需求。每次让一个进程完成并释放资源，
其余进程也可以依次完成。

当 K = 4 时，4 个进程可以各持有 2 台打印机，占满全部 8 台。
如果每个进程都需要再获得 1 台才能完成，它们就会相互等待，形成死锁。


2. 银行家算法与死锁判断

剩余需求 Need = Maximum − Allocation。

进程   R1  R2  R3  R4
P1      0   0   0   0
P2      0   7   5   0
P3      6   6   2   2
P4      2   0   0   2
P5      0   3   2   0

(a) 当前处于安全状态。一条安全序列是 P1 → P4 → P5 → P2 → P3。
    每一步选中的进程，其剩余需求都能由当时的可用资源满足。
    各进程完成并释放资源后，可用向量依次变化如下。

    初始 (2,1,0,0) → P1 后 (2,1,1,2) → P4 后 (4,4,6,6)
                   → P5 后 (4,7,9,8) → P2 后 (6,7,9,8)
                   → P3 后 (6,7,12,12)

(b) 当前没有发生死锁。题目给定没有尚未满足的挂起请求，
    因此当前没有进程因等待资源请求得到满足而阻塞。

(c) P3 的请求 (0,1,0,0) 满足剩余需求和当前可用量的限制，
    但无法安全地立即批准。试分配后，Available = (2,0,0,0)，
    P3 的剩余需求变为 (6,5,2,2)。

    安全性检查只能依次让 P1、P4、P5 完成，此时可用量为 (4,6,9,8)。
    P2 需要 7 个 R2，目前只有 6 个。P3 需要 6 个 R1，目前只有 4 个。
    因此没有安全序列。立即批准会使系统进入不安全状态。
    由于该请求已得到满足，系统此时仍没有挂起请求，也就没有立即发生死锁。

4. 所有进程同时就绪时，SJF 可以使平均等待时间最小。

在单 CPU、每个进程只有一段已知的 CPU 运行时间、忽略切换开销的
模型下，考虑相邻执行的两个进程 A 和 B，运行时间分别为 a 和 b。
若 a > b，且这两个进程从时刻 t 开始执行，则先运行 A 时，
两者的等待时间之和为 2t + a。交换顺序后为 2t + b，
减少了 a − b。其他进程的等待时间不变，因为这两段运行时间的总和不变。

对任何执行顺序，反复交换相邻的「长进程在短进程前」的组合，
最终就得到按运行时间从短到长排列的 SJF 顺序。交换过程不会增加
总等待时间，而进程数固定，因此 SJF 也使平均等待时间最小。

即使允许抢占，结论也成立。按任一抢占式调度的完成顺序逐个连续执行，
排在第 k 位的进程会在前 k 个进程的运行时间之和处完成。
原调度到第 k 个进程完成时至少也消耗了这么多 CPU 时间，
所以改成连续执行后，每个进程的完成时间和等待时间都不会增加。


5. 多级队列调度与多级反馈队列调度

共同点
两者都把就绪进程放入多个队列。每个队列可以采用自己的调度算法，
队列之间可以按优先级选取进程，也可以划分 CPU 时间。

多级队列调度
进程通常按类型或预设优先级进入固定队列，例如前台进程进入交互队列，
后台进程进入批处理队列。进程的队列归属通常保持固定。

多级反馈队列调度
系统可以根据进程的运行行为调整其所在队列。例如，持续用完时间片的
进程可以降到较低优先级，长时间等待的进程可以提升优先级。
这样既能让交互进程较快得到响应，也能缓解低优先级进程的饥饿。
