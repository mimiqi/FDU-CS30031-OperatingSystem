# Alarm 技术指导

## 1 完成目标

本模块对应课件第 46 至 51 页，实现两个系统调用：

- `sigalarm(n, handler)`：进程每消耗约 n 个用户态时钟 tick，转去执行用户处理函数。
- `sigreturn()`：处理函数完成后恢复被打断的执行现场，继续原程序。

`sigalarm(0, 0)` 关闭后续定时通知。处理函数尚未完成时，不能再次进入同一个处理函数。

本次只提供指导和参考代码，不要求实际运行。文中的命令只供以后在 VMware Ubuntu 24 验证，不能视为已通过的测试。

## 2 先理解任务的难点

系统调用本身不复杂，难点是“让用户程序临时去执行另一个函数，再像什么都没发生一样继续”。

处理器在用户态发生陷阱后，`uservec` 保存用户寄存器，`usertrap()` 保存用户程序计数器到 `trapframe->epc`。返回用户态时，`usertrapret()` 使用这个 `epc` 设置 `sepc`，最后由 `sret` 恢复执行。

因此不需要在内核中直接调用用户函数。定时到达时，先备份完整 trapframe，再把 `epc` 改为用户 handler 的地址。正常的返回路径会把进程送到 handler。

handler 不是普通 C 调用进入的：没有专门为它建立返回到被中断位置的 `ra`，所以不能靠普通 `return` 完成恢复。它必须调用 `sigreturn()`，由内核恢复原先的寄存器和程序计数器。

本实现只在 `usertrap()` 收到时钟中断时计数，不把全局 `ticks` 差值当成此进程的 CPU 时间。进程睡眠、等待或没有运行时，不应仅因墙钟经过而累计本方案的 tick。

## 3 课件中两处容易混淆的表述

课件第 50 页提到在 `sys_sigalarm()` 保存中断时寄存器。准确位置应是 **`usertrap()` 中真正决定触发 handler 的那一刻**。`sys_sigalarm()` 只是登记 interval 和地址，登记时现场并不是后来需要恢复的中断现场。

同页关于返回值覆盖 `a0` 的提醒，恢复路径里真正需要特别处理的是 **`sys_sigreturn()`**。系统调用分发器会执行：

```c
p->trapframe->a0 = syscalls[num]();
```

因此即使 `sys_sigreturn()` 已恢复完整 trapframe，若它最后直接返回 0，分发器仍会把刚恢复的 `a0` 改成 0。

这两点按本地源码中的实际控制流程理解，不能机械照抄课件的函数名。

## 4 修改文件概览

本参考方案修改 11 个文件：

- `Makefile`：把 alarmtest 加入用户程序。
- `user/user.h`、`user/usys.pl`：声明及生成系统调用入口。
- `kernel/syscall.h`、`kernel/syscall.c`：分配编号、注册处理函数。
- `kernel/proc.h`：保存每进程的定时器状态和备份现场。
- `kernel/proc.c`、`kernel/defs.h`：初始化与清理定时器状态。
- `kernel/exec.c`：成功替换程序后关闭旧 handler。
- `kernel/sysproc.c`：实现登记和恢复。
- `kernel/trap.c`：时钟触发、备份现场、转向 handler。

其中成功 exec 后清理属于本方案补充的生命周期处理；核心课程目标仍是定时触发、恢复和防重入。

## 5 阶段一 接通用户接口

### Makefile

本基线已有 `traps` 条件区块，改成：

```make
ifeq ($(LAB),traps)
UPROGS += \
	$U/_call\
	$U/_bttest\
	$U/_alarmtest
endif
```

保留原有 call、bttest，注意续行符。

### user/user.h

在系统调用原型区追加：

```c
int sigalarm(int ticks, void (*handler)(void));
int sigreturn(void);
```

`handler` 是一个无参数、无返回值的用户函数指针。

### user/usys.pl

追加：

```perl
entry("sigalarm");
entry("sigreturn");
```

不要直接编辑自动生成的 `user/usys.S`。

### kernel/syscall.h

干净的 `traps` 分支最后一个原有编号为 21，因此本方案添加：

```c
#define SYS_sigalarm  22
#define SYS_sigreturn 23
```

`syscall` 分支的 Trace 也使用 22，但属于另一个分支，不能把两个编号文件整份混用。

### kernel/syscall.c

在其他处理函数声明之后追加：

```c
extern uint64 sys_sigalarm(void);
extern uint64 sys_sigreturn(void);
```

在 `syscalls[]` 中追加：

```c
[SYS_sigalarm]  sys_sigalarm,
[SYS_sigreturn] sys_sigreturn,
```

保留原有的 `syscall()` 分发逻辑，不需要为 `sigreturn` 在分发器中另加特殊分支。我们通过返回原 `a0` 解决覆盖问题。

## 6 阶段二 保存每个进程的状态

### kernel/proc.h

在 `struct proc` 中加入：

```c
int alarm_interval;
int alarm_ticks;
uint64 alarm_handler;
int alarm_active;
struct trapframe alarm_saved;
```

`alarm_interval` 是间隔，0 表示关闭。`alarm_ticks` 是当前已累计的 tick。`alarm_handler` 是用户虚拟地址。`alarm_active` 表示当前是否正在处理通知，`alarm_saved` 保存被打断的现场。

这里把一份 trapframe 直接嵌入 `struct proc`，因此不用额外 `kalloc()` 一页，也不存在另一个备份指针的分配失败或释放遗漏。备份位于内核内存，用户程序不能直接修改它。

不能写成 `p->alarm_saved = p->trapframe` 这样的指针共享。当前 trapframe 会在 handler 的后续陷阱中被覆盖，恢复所需的是独立的内容副本。

### kernel/proc.c 和 defs.h

在 `kernel/proc.c` 中添加：

```c
void
alarmreset(struct proc *p)
{
  p->alarm_interval = 0;
  p->alarm_ticks = 0;
  p->alarm_handler = 0;
  p->alarm_active = 0;
  memset(&p->alarm_saved, 0, sizeof(p->alarm_saved));
}
```

在 `kernel/defs.h` 的 proc.c 声明区域追加：

```c
void alarmreset(struct proc*);
```

在 `allocproc()` 的 `found:` 处、设置 `p->state = USED` 后调用 `alarmreset(p)`。在 `freeproc()` 设置 `p->state = UNUSED` 前也调用一次，避免复用旧进程槽位时带着过期状态。

本方案新建子进程默认关闭 Alarm，不在 `fork()` 中复制父进程的定时器配置。课件没有要求 Alarm 的继承规则；这与 Trace 明确要求 fork 继承不同。此处是教学实现的策略，不代表完整 POSIX 信号语义。

### kernel/exec.c

在成功提交新程序映像后，设置完 `epc`、`sp`，再添加：

```c
alarmreset(p);
```

不要在 exec 开头就清理，因为 exec 可能失败，失败时原程序应继续运行。成功 exec 后旧 handler 的虚拟地址已经没有原来的含义，应关闭它，防止之后跳进新程序的错误位置。

## 7 阶段三 登记 sigalarm

在 `kernel/sysproc.c` 已有 include 后添加：

```c
uint64
sys_sigalarm(void)
{
  int interval;
  uint64 handler;
  struct proc *p = myproc();

  argint(0, &interval);
  argaddr(1, &handler);
  if(interval < 0)
    return -1;

  p->alarm_interval = interval;
  p->alarm_handler = handler;
  p->alarm_ticks = 0;
  return 0;
}
```

2024 基线的 `argint()`、`argaddr()` 返回 `void`，不能把它们作为 `< 0` 条件。

handler 地址为 0 时不一定非法：用户程序可能把有效代码放在地址 0。是否启用 Alarm 应根据 `interval > 0` 判断，不能额外要求 `handler != 0`。

**这里不能清除 `alarm_active` 或 `alarm_saved`。** 测试中的 handler 会先调用 `sigalarm(0, 0)` 关闭后续通知，再调用 `sigreturn()`。如果关闭操作顺便擦掉备份或活动标记，就无法完成当前这一次恢复。

本实现拒绝负间隔。它没有进一步验证 handler 是否指向可执行用户页面；无效 handler 在返回用户态后会触发用户异常，属于这个教学接口的限制，不应把此实现当作生产信号子系统。

## 8 阶段四 在时钟中断中触发

在 `kernel/trap.c` 的 `usertrap()` 中找到原来的：

```c
if(which_dev == 2)
  yield();
```

替换为：

```c
if(which_dev == 2){
  if(p->alarm_interval > 0 && !p->alarm_active){
    p->alarm_ticks++;
    if(p->alarm_ticks >= p->alarm_interval){
      p->alarm_saved = *p->trapframe;
      p->alarm_active = 1;
      p->alarm_ticks = 0;
      p->trapframe->epc = p->alarm_handler;
    }
  }
  yield();
}
```

这段放在原来的 `if(killed(p)) exit(-1)` 之后、`usertrapret()` 之前，只修改 `usertrap()`，不在 `kerneltrap()` 或全局 `clockintr()` 中重复加计数。

顺序十分重要：先复制现场，再改变 `epc`，否则备份里会保存 handler 自己的地址。`alarm_active` 应在返回用户态前置 1，后续时钟中断才能跳过再次触发。

处理函数执行期间本方案暂停累计下一次通知的 tick；调用 `sigreturn()` 后重新从零累计。原有 `yield()` 必须保留，不能为了 Alarm 取消时钟驱动的调度。

这一步只修改用户态恢复位置，不会在内核态执行 handler，也不需要直接改写 C 的函数返回地址。

## 9 阶段五 恢复 sigreturn

在 `kernel/sysproc.c` 添加：

```c
uint64
sys_sigreturn(void)
{
  struct proc *p = myproc();
  if(!p->alarm_active)
    return -1;

  uint64 saved_a0 = p->alarm_saved.a0;
  *p->trapframe = p->alarm_saved;
  p->alarm_active = 0;
  p->alarm_ticks = 0;
  return saved_a0;
}
```

要恢复的不只是 `epc`，还包括参数、临时寄存器、栈指针、返回地址以及其他用户寄存器。否则原程序中的循环计数、指针或计算结果可能被 handler 改坏。

`return saved_a0` 使系统调用分发器写回的仍是原来那个 `a0`，而不是 0。用户头文件里 `sigreturn` 的返回类型虽然为 `int`，但内核处理函数按 `uint64` 保存和返回完整寄存器位模式；成功恢复不会正常回到 handler 中调用 `sigreturn()` 后面的语句。

整个 trapframe 的副本也带有内核辅助字段。返回前 `usertrapret()` 会重新设置 `kernel_satp`、`kernel_sp`、`kernel_trap`、`kernel_hartid`，不依赖备份中的旧 hart 值。

`sigreturn()` 只在确有活动 handler 时接受恢复请求，避免普通程序在从未保存现场时恢复一份空备份。

## 10 用户 handler 应怎样写

原版 `user/alarmtest.c` 已提供处理函数。最小形式如下，仅用于解释调用约定：

```c
void
periodic(void)
{
  printf("alarm!\n");
  sigreturn();
}
```

如果希望本次处理后停止通知，可在 `sigreturn()` 前调用 `sigalarm(0, 0)`。不要把 handler 改成普通 `return`，也不要为获得通过结果而删掉原版测试中的困难部分。

## 11 四个测试分别检查什么

以下分析依据本地原版 `user/alarmtest.c`，不是已经运行得到的结论。

- `test0`：确认处理函数至少被调用一次。主要检查接口、计数和跳转是否接通。
- `test1`：确认能够多次通知，并且恢复后继续正确执行循环。主要检查完整现场及正确恢复位置。
- `test2`：让 handler 长时间运行，确认不会被自身重新打断。handler 还会先关闭通知，再恢复现场，因此能暴露“关闭操作擦掉恢复状态”的错误。
- `test3`：把 `a0` 设置成特定值，确认恢复后仍保持不变，专门检查分发器返回值覆盖问题。

通过 test0 只说明“跳过去了”，不代表 Alarm 完成。完整目标还包括 test1、test2、test3 和其他内核功能不被破坏。

## 13 常见错误

### 编译或链接说找不到 sigalarm

按顺序检查 user.h 原型、usys.pl 入口、syscall.h 编号和 syscall.c 分发表。检查 Makefile 是否加入 alarmtest。

### alarm 一次也不触发

检查计数是否放在 usertrap 的 `which_dev == 2` 分支中，是否把间隔误写成局部变量，或是否错误地禁止地址为 0 的 handler。

### 能打印 alarm 但随后异常或循环结果错误

检查是否先备份再修改 epc、是否只保存了 PC、是否让备份与当前 trapframe 指向同一份可变内容、handler 是否调用 sigreturn。

### handler 不断嵌套进入

检查 `alarm_active` 是否在触发前置 1，以及处理中是否跳过再次触发。不要在 sys_sigalarm 中直接清除此标记。

### test2 或 test3 失败

test2 重点检查关闭通知是否保留当前恢复状态。test3 重点检查 sys_sigreturn 是否返回原 a0，而非直接返回 0。

### 普通程序出现奇怪的定时跳转

检查 allocproc 初始化、freeproc 清理，以及成功 exec 后是否保留了旧 handler 地址。定时器状态必须按进程保存。
