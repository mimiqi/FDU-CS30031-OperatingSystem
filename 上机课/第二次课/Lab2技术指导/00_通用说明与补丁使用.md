# Lab2 通用说明与补丁使用

## 1 学习范围与环境

本包完成四个模块的指导材料：Trace、RISC-V 问答、Backtrace、Alarm。Attack 暂时跳过。本阶段可以只阅读，不需要启动虚拟机或运行测试。

后续如需动手，所有实验命令都在 VMware 的 Ubuntu 24 中执行。Windows 仅保存和传递本包，不安装或运行 xv6 工具链，也不使用 WSL。下面写明“Ubuntu 终端”和“xv6 shell”的命令属于不同环境。

Ubuntu 终端运行 `git`、`make`、交叉编译器和 `addr2line`。`make qemu` 启动 xv6 后出现的 `$` 是 xv6 shell，只运行 xv6 中的程序。退出 QEMU 的按键为先按 `Ctrl+A`，松开后再按 `X`。

## 2 两个实验分支

Trace 属于 `syscall`；RISC-V、Backtrace 和 Alarm 属于 `traps`。这不是一个分支上按顺序累积所有功能的项目。

本包使用 `xv6-labs-2024`，不要直接套用到第一次实验的新版 `xv6-riscv`。为了避免切换分支时覆盖已有实验，建议将来在 Ubuntu 分别保存两份工作目录，例如：

```text
~/os/lab2-syscall    syscall 分支，只做 Trace
~/os/lab2-traps      traps 分支，做 RISC-V、Backtrace、Alarm
~/lab2-reference    从 Windows 复制进来的指导包
```

如果目录还不存在，可在 Ubuntu 终端准备：

```sh
mkdir -p ~/os
cd ~/os
git clone --branch syscall --single-branch git://g.csail.mit.edu/xv6-labs-2024 lab2-syscall
git clone --branch traps --single-branch git://g.csail.mit.edu/xv6-labs-2024 lab2-traps
```

这些命令只是将来的操作示例，本次没有执行。若目录已存在，先检查 `git status --short`，不要直接覆盖。若网络无法访问官方仓库，可使用老师提供的同版源码，不要随意替换成新版仓库。

## 3 工具准备

已配置过的工具无需重复安装。Ubuntu 24 缺少工具时，可使用：

```sh
sudo apt update
sudo apt install git build-essential perl python3 gdb-multiarch qemu-system-misc gcc-riscv64-linux-gnu binutils-riscv64-linux-gnu
```

普通的 Ubuntu `gcc` 只能编译宿主工具，不能替代 RISC-V 交叉编译器。Makefile 通常可以自动识别 `riscv64-linux-gnu-` 或 `riscv64-unknown-elf-` 前缀。具体配置也可参考 [MIT 工具说明](https://pdos.csail.mit.edu/6.1810/2024/tools.html)。

## 4 复制学习包

把本包解压后的内容复制到 Ubuntu 中，例如 `~/lab2-reference`。该目录下应直接出现 `README.md`、`01_Trace`、`03_RISC-V`、`04_Backtrace` 和 `05_Alarm`。

本包只包含指导、补丁和修改文件，不是完整的 xv6 仓库。不要在 `~/lab2-reference` 中执行 `make qemu`；真正的构建目录是 `~/os/lab2-syscall` 或 `~/os/lab2-traps`。

## 5 两种实现方式

### 手动学习方式

按技术指导逐个文件修改，参考补丁理解新增行。已经手动完成的代码不要再应用同功能的整份补丁。

### 补丁对照方式

在匹配基线的干净工作目录先执行 `git apply --check`，成功后再应用。不匹配时应对照代码处理，不能强行覆盖。

Trace 示例，在 Ubuntu 终端执行：

```sh
cd ~/os/lab2-syscall
git branch --show-current
git rev-parse HEAD
git status --short
git apply --check "$HOME/lab2-reference/01_Trace/参考代码/trace.patch"
git apply "$HOME/lab2-reference/01_Trace/参考代码/trace.patch"
git diff --check
```

Traps 按模块顺序应用：

```sh
cd ~/os/lab2-traps
git branch --show-current
git rev-parse HEAD
git status --short
git apply --check "$HOME/lab2-reference/04_Backtrace/参考代码/backtrace.patch"
git apply "$HOME/lab2-reference/04_Backtrace/参考代码/backtrace.patch"
git apply --check "$HOME/lab2-reference/05_Alarm/参考代码/alarm.patch"
git apply "$HOME/lab2-reference/05_Alarm/参考代码/alarm.patch"
git diff --check
```

如果不想分两步，在**尚未应用任何 Traps 修改的干净基线**上改用：

```sh
git apply --check "$HOME/lab2-reference/参考补丁/traps-all.patch"
git apply "$HOME/lab2-reference/参考补丁/traps-all.patch"
```

两种 Traps 方式二选一。Alarm 的模块补丁是在 Backtrace 完成状态之上生成的；它的完整源文件也包含两模块重叠文件中已有的 Backtrace 修改。

## 6 编号不能跨分支混用

`syscall` 分支的参考实现使用 `SYS_trace = 22`。`traps` 分支使用 `SYS_sigalarm = 22`、`SYS_sigreturn = 23`。它们属于不同分支，因此没有冲突。

若自行把两个实验合并到一个内核，则必须重新分配编号并同步用户入口和内核分发表。本包不提供这种跨分支合并方案。

## 7 如何理解验证状态

本包的静态核对确认补丁能对应指定源码、按模块组合一致、文档引用的文件存在。它不能证明代码已经通过编译或功能测试。

各模块的可选验收章节给出后续应观察的行为。没有执行的测试应写“未运行”，不应填写虚构输出、地址、截图或分数。依赖编译版本的 RISC-V 地址题也保留真实填写位置。
