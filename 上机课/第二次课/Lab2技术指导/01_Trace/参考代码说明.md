# Trace 参考代码说明

## 包含哪些内容

- `参考代码/trace.patch`：Trace 完整修改补丁。
- `参考代码/修改后文件/`：八份完整源文件，与补丁对应。
- `参考代码/LICENSE.xv6`：原 xv6 源码的 MIT 许可声明。

对应的八个文件为 `Makefile`、`user/user.h`、`user/usys.pl`、`kernel/syscall.h`、`kernel/proc.h`、`kernel/proc.c`、`kernel/sysproc.c` 和 `kernel/syscall.c`。

本模块没有修改 `user/attack.c`、内存分配器或测试程序。参考目录是对照材料，不是包含全部文件的可独立编译 xv6 项目。

## 方法一 按指导手动实现

推荐先跟着技术指导的四个实践阶段修改，阅读参考源码和补丁中的新增行。每完成一个阶段，就执行相应检查。

选择此方式后，不要再向已经完成修改的仓库应用整个补丁，否则会重复添加声明和函数。

## 方法二 在干净的分支上应用补丁

将整个 `Lab2技术指导` 文件夹复制进 Ubuntu。例如放在 `~/lab2-reference`。复制后使用 Ubuntu 文件管理器确认能看到 `README.md` 和 `01_Trace`，下面以这个路径为例。

在 **Ubuntu 终端**执行：

```sh
cd ~/os/lab2-syscall
git branch --show-current
git status --short
git rev-parse HEAD
```

确认当前为 `syscall`，工作区没有需要保留的未提交改动。若你已手动写了 Trace，使用方法一继续对照，不要切换成整包覆盖。

先检查，不修改：

```sh
git apply --check "$HOME/lab2-reference/01_Trace/参考代码/trace.patch"
```

没有输出且退出成功，说明当前源文件可以接收补丁。然后应用：

```sh
git apply "$HOME/lab2-reference/01_Trace/参考代码/trace.patch"
git diff --stat
git diff --check
make clean
make CPUS=1 qemu
```

`git diff --stat` 应显示前述八个文件。进入 xv6 后按技术指导执行测试。Windows 路径 `D:\Text\...` 不能直接替代 Ubuntu 中的 `$HOME/lab2-reference/...`。
