# RISC-V 技术指导与中文参考答案

## 1 本模块要解决的问题

本模块对应课件第 35 至 40 页，不需要新增系统调用。目标是读懂 `user/call.c` 及其汇编，回答六个关于参数传递、编译优化、函数地址、返回地址、大小端和可变参数的问题。

本次只提供指导和参考答案，不要求运行。第 3、4 题的具体地址由编译器、链接结果决定；没有你的 `call.asm`，不能负责任地填一个固定地址。文末附带可填写的答案文件。

## 2 先看源程序

`traps` 基线中的 `user/call.c` 核心代码是：

```c
int g(int x) {
  return x+3;
}

int f(int x) {
  return g(x);
}

void main(void) {
  printf("%d %d\n", f(8)+1, 13);
  exit(0);
}
```

从 C 语言可知 `f(8)+1` 等于 12，因此正常语义是打印 `12 13`。但汇编不一定保留对 `f`、`g` 的调用：编译器可以把函数展开，并把常量表达式直接算完。

基线 Makefile 使用 `-O` 优化和 `-fno-omit-frame-pointer`。理解问题时应同时看 C 的含义与优化后的汇编，不能把源码中的每个函数调用机械地对应成一条跳转指令。

## 3 最少需要掌握的寄存器和指令

`a0` 至 `a7` 用于传递整数或指针参数；参数过多时还会使用栈。普通整数返回值通常放在 `a0`。`ra` 保存函数调用的返回地址，`sp` 是当前栈指针，`s0` 也叫 `fp`，在本实验的编译配置下用作帧指针。

`li` 表示装载立即数，`mv` 表示复制寄存器，`addi` 做加立即数，`ld` 和 `sd` 分别从内存读取、向内存保存 64 位值。`jal`、`jalr` 用于跳转并建立返回地址，`ret` 是返回的伪指令。

`auipc` 常与 `jalr` 配合构成较远的 PC 相对调用。因此函数调用可能占两条指令，也可能被链接器改写成较短形式。读取 `ra` 时应找到实际建立返回地址的那条指令，而不是只看前面的 `auipc`。

普通函数调用和系统调用不要混淆：普通 `printf` 调用按函数调用约定传参；执行系统调用入口时，`a7` 又被用来放系统调用编号，`ecall` 使处理器进入陷阱流程。

## 5 第一题 参数放在哪些寄存器

题意：函数参数通过什么寄存器传递？`main` 调用 `printf` 时，13 在哪个寄存器中？

参考答案：RISC-V 的整数调用约定使用 `a0` 至 `a7` 依次传递整数或指针参数。本例中 `printf` 的第一个参数是格式字符串地址，放在 `a0`；第二个参数是 `f(8)+1`，即 12，放在 `a1`；第三个参数是 13，放在 `a2`。

注意格式字符串也算一个参数。不能因为 13 是第二个被打印的数字，就把它写成 `a1`。在汇编中可寻找对 `a2` 装载 13 的指令。

## 6 第二题 为什么找不到 f 或 g 的调用

题意：`main` 中哪里调用 `f`？哪里调用 `g`？

参考答案：在此基线的优化配置下，编译器通常会内联 `f`、`g`，并把 `f(8)+1` 常量折叠为 12，因此 `main` 中可能没有调用它们的 `jal` 或 `jalr`，而是直接准备数值 12 作为 `printf` 参数。

`call.asm` 中仍可能存在独立的 `<f>:` 和 `<g>:` 定义；函数定义存在不代表 `main` 实际调用它们。应根据 `main` 的指令判断。

若自己的工具链确实保留了调用，就写出真实的调用指令及地址，不应为了套参考答案坚持说“没有调用”。课件要求答案与自己的汇编一致。

## 7 第三题 printf 的地址

题意：`printf` 函数位于什么地址？

在 `user/call.asm` 中查找类似下面的标签：

```text
<本次构建的地址> <printf>:
```

标签左边就是这份用户可执行程序中 `printf` 的入口地址。若查看的是调用行，也应区分调用指令自身地址和被调用目标地址。

参考填写方式：

```text
printf 的入口地址是 0x________。
依据：user/call.asm 中 <printf>: 标签前的地址。
```

这不是宿主 Ubuntu 的 libc `printf` 地址，也不是 `kernel/printf.c` 的地址。编译配置、链接顺序或程序修改都可能改变它。

## 8 第四题 jalr 之后 ra 是多少

题意：`main` 调用 `printf` 的 `jalr` 刚执行完时，`ra` 中保存什么值？

参考答案：`ra` 保存调用之后下一条指令的地址，以便 `printf` 返回时继续执行 `main`。这里问的是调用刚完成跳转时的链接地址，不是函数入口地址，也不是 `printf` 执行若干内部调用之后的现场。

对标准 32 位 `jalr`，如果它的地址是 `A`，返回地址就是 `A+4`。若最终使用 16 位压缩调用指令 `c.jalr`，返回地址为 `A+2`。最稳妥的做法是直接读取反汇编中调用之后下一条指令的地址。

参考填写方式：

```text
调用 printf 的实际跳转指令地址是 0x________。
调用后下一条指令地址是 0x________，因此 ra 为 0x________。
```

不能一律对 `auipc` 的地址加 4，也不能对所有反汇编中显示为 `jalr` 的形式盲目加 4。应结合实际编码长度和下一条指令地址。

## 9 第五题 大小端与格式化输出

题目给出：

```c
unsigned int i = 0x00646c72;
printf("H%x Wo%s", 57616, (char *)&i);
```

### 小端下如何解释

57616 的十六进制数值为 `E110`。`i` 是一个 4 字节无符号整数，小端内存按地址从低到高保存为：

```text
72 6c 64 00
 r  l  d \0
```

`%s` 从 `(char *)&i` 指向的字节开始读取，把它们当成以零字节结尾的字符串，因此得到 `rld`。`Wo` 与 `rld` 拼起来成为 `World`。

**本包的 2024 基线输出应按源码推导为 `HE110 World`，不含自动追加的换行。** `user/printf.c` 的十六进制字符表是 `0123456789ABCDEF`，因此 `%x` 使用大写字母。若在标准 libc 中运行同一表达式，通常会显示小写 `He110 World`；不要把不同 printf 实现的大小写混为一谈。

这里的 `E110` 由字符 `E`、数字 `1`、数字 `1`、数字 `0` 组成，不是英文单词 `ello`。

### 如果假设处理器改成大端

为了让内存中从低地址开始仍然是 `72 6c 64 00`，应把 `i` 改为 `0x726c6400`。

不需要改变 57616，因为 `%x` 按整数的数值转换成文本，不把这个整数的内存字节当作字符串。变化的是 `%s` 对内存字节序列的解释。这个问题是理论假设，不要求改造 QEMU 或工具链使实验真正运行在大端上。

### 可选演示代码

附带的 [endian.c](参考代码/endian.c) 是一个独立 xv6 用户程序，使用正确的 `(char *)&i` 类型转换，并显示字节顺序。它不是必交内核修改，也没有被加入参考内核补丁。

将来若要演示，可把它复制为 `user/endian.c`，在 Makefile 的 `traps` 用户程序列表中加入 `$U/_endian`，然后在 xv6 shell 运行 `endian`。本次没有执行。

## 10 第六题 缺少可变参数会输出什么

题目给出：

```c
printf("x=%d y=%d", 3);
```

参考答案：不能确定 `y=` 后的数值。格式字符串要求两个整数参数，但实际只提供了一个。`printf` 读取不存在的第二个可变参数属于 C 语言未定义行为。

从此实验的调用约定看，格式串在 `a0`，3 在 `a1`，第二个被打印的整数原本应在 `a2`。调用者没有提供对应参数，因而可能读取 `a2` 当时的残留内容；具体表现依赖编译器和程序现场。

不能回答“一定是 0”“一定是随机数”或“一定是 3”。“残留内容”说明常见的底层机制，正式结论仍是未定义行为，而不是某个固定数值。

本仓库的 `printf` 声明带有格式检查属性，并且开启 `-Werror`；直接把这行放入程序可能产生缺少参数的编译错误。无需为了实验故意关闭编译警告来观察一个没有标准保证的值。
