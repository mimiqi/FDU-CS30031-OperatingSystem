# Backtrace 技术指导

## 1 完成目标

本模块对应课件第 41 至 45 页。在 `kernel/printf.c` 实现 `backtrace()`，沿当前内核调用栈打印返回地址；在 `sys_sleep()` 中调用它，使 `bttest` 能观察调用链；最后接入 `panic()`，方便发生内核错误时查看路径。

本次交付指导、补丁和参考源码，不要求现在编译或运行。后面的验收方式仅供将来在 VMware Ubuntu 24 使用。

## 2 栈帧与两个固定偏移

函数调用时，调用者的返回地址和帧指针会保存在栈中。RISC-V 的栈向低地址增长，而本实验的 Makefile 保留帧指针。对当前帧指针 `fp`，可按以下位置读取：

```text
fp       当前栈帧的上边界
fp - 8   当前函数保存的返回地址 ra
fp - 16  调用者的帧指针 previous_fp
更低处   局部变量、其他保存的寄存器等
```

`s0` 保存当前帧指针。回溯时打印 `*(fp-8)`，再把 `fp` 改成 `*(fp-16)`，继续处理上一层。

这里的“上一层”指更早进入的调用者。因为栈向低地址增长，合法调用者的 `fp` 应比当前 `fp` 大。不要根据变量名“previous”误以为地址也应减小。

这不是扫描整个栈寻找看起来像地址的数，也不是使用 C 递归函数模拟调用链；顺着保存在栈里的帧指针链做循环即可。

## 3 为什么必须有终止条件

xv6 给每个进程分配一页内核栈，旁边有未映射的保护页。如果一直追踪下去，最终会越过栈边界，反而制造新的内核异常。

参考实现把读取限制在初始栈页内，并检查：

- `fp-16` 和 `fp-8` 都位于当前栈页中。
- `fp` 满足 16 字节对齐。
- 下一帧必须向高地址前进，避免原地循环。
- 下一帧必须严格小于本页上边界。

用 `PGROUNDDOWN(fp - 1)` 确定初始栈页，可以避免初始帧指针位于页边界时选中下一页。但这不表示应打印 `fp == high` 的帧：在本实验的用户陷阱路径中，最外层 `usertrap` 帧指针可位于栈页上界，其保存的 `ra` 不保证是内核返回地址。陷阱入口通过不改写 `ra` 的跳转进入 `usertrap`，因此可能保留用户态值。回溯到该帧时，应停止读取其返回地址；循环使用严格的 `fp < high`。

这是一份适用于本实验栈布局的回溯器，不是通用的 DWARF 展开器。对于已严重损坏的栈，它只能尽力输出，不能保证恢复完整调用链。

## 4 修改一 读取 s0

在 `kernel/riscv.h` 的 C 代码区域，即 `#ifndef __ASSEMBLER__` 与对应 `#endif` 之间，加入：

```c
static inline uint64
r_fp()
{
  uint64 x;
  asm volatile("mv %0, s0" : "=r" (x));
  return x;
}
```

`asm volatile` 是内联汇编，作用是把 `s0` 的当前值复制到 C 变量 `x` 中。这里不改变栈，也不改变 `s0`。

不要把 C 函数放到汇编保护区之外，否则同样包含此头文件的汇编源文件可能无法处理它。

## 5 修改二 添加声明

在 `kernel/defs.h` 的 `printf.c` 声明区域追加：

```c
void backtrace(void);
```

这样 `sys_sleep()` 等其他源文件才能调用它。声明不等于实现，真正的函数体在下一步。

## 6 修改三 实现回溯函数

在 `kernel/printf.c` 中、`panic()` 之前加入：

```c
void
backtrace(void)
{
  uint64 fp = r_fp();
  uint64 low = PGROUNDDOWN(fp - 1);
  uint64 high = low + PGSIZE;

  printf("backtrace:\n");
  while(fp >= low + 16 && fp < high && (fp & 15) == 0){
    uint64 ra = *(uint64 *)(fp - 8);
    uint64 previous = *(uint64 *)(fp - 16);
    printf("%p\n", (void *)ra);
    if(previous <= fp || previous >= high)
      break;
    fp = previous;
  }
}
```

`uint64` 是 64 位整数，能够保存本实验的地址。转换为 `uint64 *` 后解引用，读取栈中实际保存的 8 字节。

`%p` 对应指针格式，`(void *)ra` 与 `printf` 的格式检查一致。输出的是每一层保存的返回位置，不是函数入口地址。通过这些位置，可以判断“这个函数返回后会回到调用者的哪里”。

下一帧的对齐检查由下一次循环入口完成。所有解引用均发生在边界检查之后。

## 7 修改四 接入 sys_sleep

在 `kernel/sysproc.c` 的 `sys_sleep()` 中，读取并处理 `n` 之后、获取 `tickslock` 之前调用：

```c
argint(0, &n);
if(n < 0)
  n = 0;
backtrace();
acquire(&tickslock);
```

保留该函数其他逻辑。`user/bttest.c` 调用 `sleep()` 后，系统调用进入 `sys_sleep()`，因此可以观察这条调用链。

本基线 Makefile 已将 `_bttest` 放在 `traps` 的用户程序列表中，无需再重复添加。

## 8 修改五 接入 panic

保留 `panic()` 原来的逻辑，在打印错误消息之后、设置 `panicked = 1` 之前调用：

```c
pr.locking = 0;
printf("panic: ");
printf("%s\n", s);
backtrace();
panicked = 1;
```

`pr.locking = 0` 是原有的 panic 处理，避免错误路径因输出锁导致进一步等待。回溯输出不能放在 `panicked = 1` 之后：该标志会让底层输出路径停止正常工作。

不要为验收故意破坏正常内核来制造 panic。课程的基本检查可以使用 `bttest`，panic 接入只需先核对代码位置。

## 9 文件清单与参考代码

本模块修改四个文件：

- `kernel/riscv.h`：读取帧指针。
- `kernel/defs.h`：声明回溯函数。
- `kernel/printf.c`：遍历帧链并接入 panic。
- `kernel/sysproc.c`：在 sys_sleep 中触发回溯。

[参考代码说明](参考代码说明.md) 解释了独立补丁与完整文件的用法。Alarm 会继续修改其中的 `defs.h`、`sysproc.c`，因此后续应先完成本模块，再使用 Alarm 的增量补丁。

## 10 可选验收

以后如需验证，在 Ubuntu 终端执行：

```sh
cd ~/os/lab2-traps
make clean
make CPUS=1 qemu
```

进入 xv6 shell 后执行：

```sh
bttest
```

预期出现 `backtrace:` 标题和十六进制返回地址，而不是内核崩溃或持续打印。本基线评分脚本预期三条地址，分别解析到 `sysproc.c`、`syscall.c`、`trap.c`。实际地址与行号依赖构建结果，不能预先写死。

退出 QEMU 后，在 Ubuntu 终端交互运行：

```sh
riscv64-linux-gnu-addr2line -f -e kernel/kernel
```

逐行粘贴自己刚刚得到的返回地址，完成后按 `Ctrl+D`。若使用另一种工具链，命令前缀可替换为 `riscv64-unknown-elf-addr2line`。

`-f` 额外显示函数名。必须使用产生这些地址的同一份 `kernel/kernel`；不要重新修改并编译后再拿旧地址解释新内核。

只检查本模块，可在 Ubuntu 终端使用：

```sh
make GRADEFLAGS=backtrace grade
```

这些是验收方法，不是本包已经取得的测试结果。

## 11 常见问题

### 只有一条地址或没有地址

检查 Makefile 是否仍保留 `-fno-omit-frame-pointer`，`r_fp()` 是否读取 `s0`，以及初始栈页和两个偏移是否计算正确。

### 多打印一条低地址，例如 0x000000000000000e

检查循环是否使用了 `fp <= high`，以及下一帧检查是否允许 `previous == high`。这会多读取最外层陷阱帧保存的值，该值可能属于用户态。应分别改为 `fp < high` 和遇到 `previous >= high` 时停止；修改后在 VMware Ubuntu 中重新执行 `bttest`，确认三条地址并解析，再进行专项评分。静态补丁检查不能代替这一步运行验证。

### 一直打印地址或回溯导致 panic

检查是否把 `fp-16` 写成了其他偏移，是否忘记在读取之前检查边界，或是否没有检查下一帧必须大于当前帧。

### addr2line 显示问号

检查工具链是否支持 RISC-V、是否使用带调试信息的当前 `kernel/kernel`、地址是否复制完整。应读取内核 ELF，不能拿 `user/_bttest` 解析内核返回地址。

### Alarm 或其他程序也打印 backtrace

参考实现保留 `sys_sleep()` 中的调用，所以任何实际调用 sleep 的用户程序都可能打印回溯。这是课件要求的观察入口，不一定说明 Alarm 出错。基线评分脚本会为 bttest 单独启动验收。
