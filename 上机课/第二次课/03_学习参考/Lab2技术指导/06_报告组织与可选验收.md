## 2 System calls 报告

建议结构为：

1. 环境与版本：VMware Ubuntu 24、工具链、xv6-labs-2024 的 syscall 分支和实际提交号。
2. 系统调用路径：用户声明、入口汇编、ecall、usertrap、syscall 分发和 a0 返回值。
3. Trace 目标与设计：mask 位含义、每进程字段、初始化、fork 继承和 exec 保留。
4. 修改文件与关键代码：解释各处改动的原因，而非只粘贴完整源文件。
5. 可选实测结果：read、全部调用、普通程序、fork 继承和 Trace 自动测试。
6. Attack：结合实际实现和测试截图，说明页面复用的数据残留、代码思路及验证边界；当前完整评分已为 50/50。
7. 问题与理解：遇到的报错、对应原因，以及 mask 不能放在全局变量的理由。

如果是尚未实测的其他构建，应据实写“未运行”，不套用本项目的地址、截图或分数。本项目已经取得实测结果，应使用现有报告中的真实记录。

## 3 Traps 报告

建议结构为：

1. 环境与版本：VMware Ubuntu 24、traps 分支和实际构建工具链。
2. RISC-V 六题中文回答：特别注明第 3、4 题地址来自哪份 call.asm。
3. Backtrace 原理：帧指针、返回地址、两个固定偏移、栈页边界。
4. Backtrace 实现：四个修改文件和 panic 接入位置。
5. Alarm 原理：登记、触发、保存现场、禁止重入、恢复现场。
6. Alarm 实现：两个系统调用、进程字段、时钟处理和 a0 保持。
7. 可选验证：bttest 地址解析、alarmtest 四项、usertests 回归和完整评分。
8. 总结：系统调用与异步时钟事件的不同，为什么仅恢复 PC 不够。

参考模板位于 `03_RISC-V/answers-traps-参考.txt`，其中地址占位符不是正式答案。本项目已完成的中文回答及实际地址见 Traps 报告，正式提交不再复制未填的参考模板。

## 4 可选验收清单

本节保留为复习或重新验收时的操作清单，不意味着已经通过评分的工程需要重新应用补丁。

Trace 在 syscall 分支的 xv6 shell 中检查：

```sh
trace 32 grep hello README
trace 2147483647 grep hello README
grep hello README
trace 2 usertests forkforkfork
trace 0 grep hello README
```

退出 xv6 后，Ubuntu 终端中可只选择 Trace：

```sh
make GRADEFLAGS=trace grade
```

Traps 在自己的分支中构建，xv6 shell 依次检查：

```sh
bttest
alarmtest
usertests -q
```

在 Ubuntu 终端用相同构建产物解析 bttest 的真实返回地址。完整 `make grade` 还可能检查 `answers-traps.txt`、`time.txt` 等文件；需要时填写自己的答案和真实耗时，不复制占位模板，也不改评分脚本让它假通过。

每项记录命令、原始结果、截图和解释。子集通过不等于整个实验通过；代码核对不等于运行成功。
